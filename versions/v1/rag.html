法律文本的 6 个特性

决定了它不能按 512 字切

权威性 / 精确措辞

“应当”是强制，“可以”是授权；差一个词结论就变。切分不能改写原文，引用必须精确到条号。

时效性 / 版本

法规会修订、废止、被新法取代。元数据要带 status 和生效日期，检索前过滤，不靠模型判断。

强结构 / 坐标

编 → 章 → 节 → 条 → 款 → 项；引用是“某法第 X 条第 X 款”，天然适合按条切分。

长文本 / 跨法条

一个劳动问题要同时看劳动合同法、司法解释、实施条例；单条召回不够，需要多路召回和父子分段。

术语密集 / 坐标查询

“劳动合同法第三十九条”这类查询靠字面命中；纯向量对编号不敏感，BM25 不能省。

高风险 / 可追溯

用户要“依据”不是“总结”。材料编号、引用格式、拒答、免责声明、评测闭环，一个都不能少。

切分：固定长度 → 结构切分 → 父子分段

切完还能拼回去，才算切对

固定长度

1000 字 + 200 重叠，中文标点优先。简单、通用，但会从法条中间切开，丢掉“第 X 条”坐标。

基线

结构切分

以“条”为单位，章/节路径、条号、款/项一起入库；超长条再按款拆，但保留完整坐标。

法条主方案

父子分段

子块（款/项）负责和 query 精确匹配；父块（整条）负责给模型完整上下文；引用回到条号。

检索：BM25 为什么不能省

法律里有一半是坐标型查询
01双路召回BM25 管条号/术语；向量管同义改写
02RRF 融合1/(k+rank)，k=60；只看排名，不看分数量纲
03重排交叉编码器逐对打分，把正确条文从第 7 提到第 2
04Top 3–6编号 + 来源头进 prompt，太多会稀释注意力
查询类型例子主力辅助
语义型没签合同被开除怎么维权向量BM25
坐标型劳动合同法第三十九条说了什么BM25元数据（法规名）
术语型竞业限制期限是几年BM25向量
多跳型违法辞退能拿多少赔偿向量 + BM25重排、多轮压缩
为什么不是“向量 or BM25”：纯向量 63%，纯 BM25 71%，融合 78%。 坐标型查询靠 BM25，语义型查询靠向量；RRF 把两路排名合并，重排再做最后一道精排。

评测口径

把分母写清楚，比数字本身更加分
指标定义状态
答案级引用命中率回答引用的条文里至少一条命中 gold 条文；分母=有引用的回答团队 n≈300：63→71→78→85
引用准确率回答里的法规名 + 条号与原文一致的比例团队评测：80→93
拒答率知识库没有依据时，明确说“不确定”的比例待补
P95 延迟端到端响应时间，比平均值更能反映体验待补
边界：63/71/78/85 是团队评测数据；624 chunk 与 3 条测试问题是我个人复现。 两套数字不能相加，也不能说成“我一个人做的”。
