# 世界模型评测集（演示版）

这是给 Genie 4、Hy-Nomas、HappyOyster 三家用的**可执行评测集**。目标不是跑排行榜，而是把“同一初始状态 → 同一动作 → 同一观察点”的流程跑通，拿到可复核的录屏和分数。

## 0. 先定边界

- 每家模型跑 **2 个核心场景**（S02、S05）即可支撑一次 10–15 分钟的演示；S01/S03/S04/S06 是可选加练。
- 这是 **N=2 案例研究**，不写“谁更强”的排名；只写“这组配对里，谁在这两个场景更稳”。
- 不录音频评价；只看画面、动作响应和记忆一致性。
- 不使用腾讯内部 rubric、数据或未公开结论；下面是公开可复现的简化版。

## 1. 统一条件（三家必须一致）

| 项 | 要求 |
| --- | --- |
| 起始画面 | 同一张图；没有图就先用同一段文字生成一张静帧，三家共用 |
| 初始位姿 | 同一位置、同一朝向；录屏开头先停 2 秒 |
| 分辨率 | 720p 或以上，16:9 |
| 帧率 | 30fps 或 60fps，全程不剪辑 |
| 控制方式 | 键盘/页面动作按钮；按下面的时间轴执行，不即兴加动作 |
| 时长 | 核心场景 20 秒以内；Hy-Nomas 单次 60 秒也够 |
| 录制 | 系统录屏或模型自带回放；保留鼠标/键盘操作可见性（可选） |

文件命名：

```text
assets/world/<model-id>/<scene-id>.mp4
# 例：assets/world/genie-4/S02.mp4
```

同时在 `runs.json` 里记：`model`、`scene`、`date`、`duration_sec`、`latency_ms`、`effective_duration_sec`、四个维度分、`evidence_ts`、`note`。

## 2. 三个模型怎么进

| 模型 | 入口 | 录制注意 |
| --- | --- | --- |
| Genie 4 | Project Genie（Google Labs，需 AI Ultra） | 单次约 120 秒；先停 2 秒再动，结束前回到起点并停 2 秒 |
| Hy-Nomas | 腾讯混元官方 demo | 单次约 60 秒；动作控件/键盘按时间轴执行；录整个会话 |

> 入口和额度会变；录之前先确认当天能不能进、单次时长多少。进不去就换另一家，不要用不同条件硬拼。

## 3. 核心场景（先跑这两个）

### S02 · 绕桌一圈回起点

**考什么**：空间记忆 + 相机控制 + 指令遵循。

**起始画面提示词（生成一次，三家共用）**：

```text
一间普通室内房间，中央一张木桌，桌上左侧一个红色杯子、右侧一本合上的书；
相机在桌子正前方约 1.5 米、高度 1.4 米，平视。自然光，画面干净，无人物。
```

**给模型的指令**：

```text
从桌子正面出发，沿桌子右侧绕行一圈，回到起点，最后面向桌子。
```

**控制时间轴**：

| 时间 | 动作 |
| --- | --- |
| 0–2s | 不动，保留初始画面 |
| 2–8s | 持续向右平移/右转，绕过桌子右侧 |
| 8–12s | 继续绕到桌子背面，保持桌子在画面内 |
| 12–18s | 回到起点，停住，面向桌子 |
| 18–20s | 不动，保留回程画面 |

**看什么**：

- 回到起点时，红杯子和书的位置是否与初始一致；
- 桌子遮挡关系是否正确（近处桌腿遮远处桌腿）；
- 相机是否真的绕了一圈，而不是原地转头/瞬移；
- 回程画面有没有突然重置、物体消失、桌面比例变化。

**失败模式**：绕行中桌子消失、红杯子变成两个、回程直接切回初始帧、相机穿墙。

---

### S05 · 180 度转身

**考什么**：视角变化下的场景一致性 + 相机控制。

**起始画面提示词（生成一次，三家共用）**：

```text
一个开阔的广场，正前方有一座明显的钟楼，左侧一排矮树，右侧一栋红砖建筑；
相机站在广场中央，平视钟楼，傍晚光线。
```

**给模型的指令**：

```text
原地转身 180 度，停 2 秒，再转回 180 度，回到面向钟楼的初始视角。
```

**控制时间轴**：

| 时间 | 动作 |
| --- | --- |
| 0–2s | 不动 |
| 2–5s | 原地向右转 180 度 |
| 5–7s | 停住，观察背后场景 |
| 7–10s | 原地向左转 180 度，回到初始朝向 |
| 10–12s | 不动，保留回程画面 |

**看什么**：

- 背后场景是否合理（不是黑屏/贴图墙/重复正面）；
- 转回后钟楼、树、红砖建筑的相对位置是否漂移；
- 转身过程中透视是否连续，有没有跳切；
- 有没有把“转身”做成“镜头环绕”。

**失败模式**：转回后钟楼消失/换边、背后场景与正面重复、转身中途重置。

## 4. 可选加练（有时间再跑）

| ID | 场景 | 一句话指令 | 主要看 |
| --- | --- | --- | --- |
| S01 | 走廊左转 | 沿走廊向前走 4 秒，在第一个路口左转，停住 | 指令遵循、相机控制 |
| S03 | 推球撞瓶 | 走向桌边的红球，把球推向前方的塑料瓶 | 物理合理性、物体持久 |
| S04 | 走进水池 | 从池边走进浅水池，水花溅起后停住 | 物理合理性、材质 |
| S06 | 开门再关门 | 走到门边，推开门，走进去，再关门 | 物体交互、状态持久 |

这些场景用同样的“起始图 + 指令 + 时间轴”格式补全即可；不要一次跑太多，先把 S02/S05 跑干净。

## 5. 评分怎么填

每个场景录完后，在该模型的工作台里填：

- **指令遵循**：有没有按顺序完成动作；
- **物理合理性**：碰撞、重力、材质、穿模；
- **相机控制**：转向/位移是否跟输入一致；
- **记忆一致性**：回到同一位姿时布局、遮挡、光照是否一致；
- **交互延迟**：从按键到画面响应的大致毫秒数（目测/录屏帧差）；
- **有效时长**：画面开始崩坏/重置前，能稳定交互多少秒；
- **证据时间戳**：最关键的失败帧，例如 `00:12.5`；
- **失败模式**：一句话写“什么现象 + 可能原因”，不要只写“不好”。
